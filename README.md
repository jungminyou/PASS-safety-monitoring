# Assistive Technologies on Safety Monitoring for Community-Dwelling Persons Living with Dementia — analysis code

This repository contains the analysis code for the paper "Assistive Technologies on Safety Monitoring for Community-Dwelling Persons Living with Dementia", which has been accepted for publication in *Scientific Reports*. It covers the participant characteristics (Table 1), the sleep and in-home sensor comparison (Table 2), the participant-level prediction models (Table 3), and Figures 1–3.

## Data

The original dataset cannot be shared because it contains personal information. Instead, a synthetic dataset with the same format is provided in `synthetic_data/`. Its values are random draws generated by `synthetic_data/make_synthetic_data.py`; they are not derived from participant data, so results obtained with them do not reproduce the published values. Requests for the original data may be made to the corresponding author and are subject to privacy and ethical considerations.

## Scope

- Table 1 uses Welch's t-test for continuous variables and the chi-square test for categorical variables, or Fisher's exact test where any expected cell count is below five.
- Table 2 accounts for the clustering of days within dyads using linear mixed models with a participant random intercept, falls back to generalized estimating equations with an exchangeable working correlation when a mixed model does not converge, and applies the Benjamini–Hochberg correction across the 21 primary P values.
- Participant-level models use penalized logistic regression with an L1 or L2 penalty selected in an inner cross-validation loop, stratified group k-fold cross-validation grouped by dyad, and out-of-fold predictions averaged over two independent partitions. Uncertainty is estimated by bootstrap resampling of dyads.
- Continuous variables are scaled by min-max normalization, and missing values are imputed with the training-fold median; all transformations are fitted on the training folds only.
- Discrimination is tested against matched permutation null distributions (2,000 permutations), in which the full model-selection procedure is re-run.
- Classification thresholds are selected on the pooled out-of-fold predictions; the threshold-dependent metrics are descriptive.
- Feature contributions are examined using SHAP values computed on the out-of-fold predictions.

Supplementary analyses are not included.

## Run

Install the packages in `requirements.txt`. Input formats are documented in `INPUT_SCHEMA.md`; required fields are defined in `DATA_DICTIONARY.csv`. The output directory must be outside this package, and so must any restricted input directory; the bundled `synthetic_data/` folder is the only input allowed inside it. `code/config.py` refuses to run otherwise.

Set the input and work directories, then run the scripts in order from the `code` directory. With the synthetic dataset:

```powershell
$env:PASS_PRIVATE_DATA = "$PWD/synthetic_data"
$env:PASS_WORK_DIR = "$HOME/PASS_synthetic_run"
$env:PASS_PERMUTATIONS = "20"   # quick check; omit for the full 2,000
cd code
python table1.py              # Table 1
python table2.py              # Table 2
python participant_models.py  # Table 3, bootstrap CIs, and matched permutations
python figures.py             # Figures 1–3 (requires participant_models.py output)
```

With the original data, set `PASS_PRIVATE_DATA` to the restricted input directory instead and leave `PASS_PERMUTATIONS` unset.

Results are written to `results/`, `state/`, and `figures/` inside the work directory. The permutation count defaults to 2,000. When the original data are used, generated figures and state include participant-level information and must remain private. The figure script reads only state generated in the selected work directory.
